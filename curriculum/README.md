# Ханзи BG — учебна пътека

Тук са **ръчно написаните** файлове на учебната програма. Те не се
генерират и не се презаписват от pipeline-а: редът, в който ученикът
среща думите, е педагогическо решение, а не свойство на корпуса.

## Файловете

| Файл | Какво е |
|---|---|
| `00_intro.json` | Два урока: „Здравей“ и „Кратки думи“. Само карти, не думи — първият контакт с езика. |
| `10_hsk1.json` | 23 теми, 40 урока, 300-те думи от HSK 1, подредени за начинаещ, с шест пресипки между тях. |
| `12_hsk2to4.json` | 45 теми, 131 урока, 1678-те думи от HSK 2, 3 и 4 — по ниво, и по тема във всяко ниво. |
| `20_glosses_hsk1.json` | Ръчно написани български глоси за 300-те думи от HSK 1. |
| `21_glosses_hsk2to4.json` | Ръчно написани български глоси за 1678-те думи от HSK 2-4. |
| `30_situations.json` | Тема „Ситуации“: уроци за четене — кратки разговори, въпрос за всеки и превод на реда зад бутон „?“. |

Патчовете с глоси са отделни, не защото правилата им са
различни, а защото така една промяна в новите глоси не може да
развали изпратените. Всеки патч се проверява срещу СВОЯ файл с
пътя:

```bash
python pipeline/check_lesson_files.py curriculum/12_hsk2to4.json \
                                         curriculum/21_glosses_hsk2to4.json
```

## Кой е истинският източник

Файлът `12_hsk2to4.json` е **ръчно поддържан** и е в git. Той е
истината: редът на уроците е педагогическо решение, а глосите са
написани на ръка срещу точно тези уроци.

Скриптовете в `pipeline/` правят **чернова** от него. Черновата
НИКОГА не замества файла в git без изрично искане:

```bash
python pipeline/_build_hsk_levels.py   # списъците на думите по ниво
python pipeline/assign_themes.py        # към коя тема е всяка дума
python pipeline/build_lessons.py        # -> чернова в TMPDIR
```

`build_lessons.py` пише черновата в scratch директорията и
съобщава го. Само с `--write` замества `curriculum/12_hsk2to4.json`.

Причината е проста: чернова, която тихо презаписва ръчно
поддържан файл, унищожава и уроците, и глосите — без да даде
грешка, защото файлът все така се чете.

Черновата и файлът в git **не са едно и също**, и не бива да са:
файлът е изключван и поправян на ръка, а черновата е резултат от
алгоритъм. Затова `audit_path.py` проверява ФАЙЛА, а не черновата.

## Форматът

Два различни формата се четат от `pipeline/08_build_content_db.py`, и
се различават по съдържанието, не по името:

**Учебна пътека** — обект с ключ `units`:

```json
{
  "units": [
    {
      "key": "numbers",
      "title": "Числа",
      "lessons": [
        {
          "key": "numbers-1",
          "title": "Числа от 1 до 10",
          "words": ["一", "二", "三"]
        }
      ]
    }
  ]
}
```

Урокът с `"kind": "teach"` носи `cards` вместо `words`. Картата е:

```json
{
  "kind": "text" | "items" | "table" | "reading",
  "title": "Заглавие",
  "body": "Обяснение",
  "items": [{ "hanzi": "你好", "pinyin": "nǐ hǎo", "text": "здравей" }],
  "rows": [["b", "p"], ["d", "t"]]
}
```

Картата `"reading"` е пасаж — кратък разговор за четене:

```json
{
  "kind": "reading",
  "title": "На пазара",
  "body": "Прочети съобщението и отговори на въпроса.",
  "lines": [
    {
      "hanzi": "我要三个苹果。",
      "pinyin": "Wǒ yào sān gè píngguǒ.",
      "bg": "Искам три ябъка.",
      "audio": "reading_market_1.ogg"
    }
  ],
  "question": {
    "text": "Какво иска купувачът?",
    "options": ["Три ябъка", "Пет мандарина", "Десет ябъка"],
    "answer": 0
  }
}
```

`bg` е джокерът: преводът на реда се отваря с бутона „?“ и не се
показва преди въпроса. `audio` е името на клипа, който
`pipeline/13_build_reading_audio.py` записва в `data/audio/` — името е
договор между ръчно написания файл и pipeline-а.

**Патч с глоси** — плосък обект `йероглиф → български текст`. Той
**презаписва** машинния превод за посочените думи и те се маркират
като човешки в базата.

## Правилата

1. Всеки урок носи **8 до 15 думи**.
2. Ключовете са уникални в целия файл; ключът на урока започва с
   ключа на темата.
3. Всяка дума трябва да съществува в речника. Ако не —
   `08_build_content_db.py` спира с грешка, а не пише счупена база.
4. Заглавията са на български, кратки, без точка в края.
5. Глосите са **къси** (до 45 знака), без скоби и без „/“ — така
   формата, в който машинният превод е натрупал всичките си значения,
   не се повтаря.

## Пресипките

Уроците с ключ `x-…` са **пресипки**: те учат думи и правила, които
се появяват във всяко второ изречение и които ученикът не може да
заобиколи. Те са в пътя, а не в упражненията — минава се през тях.

Шест са, и всяка е след темата, която дава думите ѝ:

| Пресипка | След темата | Учи |
|---|---|---|
| `x-bridges` | Семейство | 是 и 的 |
| `x-order` | Време и дни | редът на думите, времето преди глагола |
| `x-measure` | Тяло и външен вид | число + броячна дума |
| `x-negative` | Път и транспорт | 不 и 没 |
| `x-aspect` | Места и посока | 了 и 在 |
| `x-question` | Въпроси и фрази | 吗 и въпросителните думи |

Правилата за тях:

1. **Една пресипка носи ЕДНО правило.** Не две. Урок, който учи
   три неща, учи нито едно.
2. **Примерите са от думите, които вече са на пътя.** Не въвеждат нови
   думи — учат как вече познатите се подреждат.
3. **Три-четири примера**, не осем. Урокът трябва да е кратък: целта
   е да не измори, а да остави правилото.
4. **Бъдат изключени** точките, които объркват повече, отколкото
   помагат. 把 и 被 са извън, докато не дойде моментът.
5. Всяка пресипка завършва с **въпрос**, за да е ясно дали е минал.

## Звукът на примерите

Примерът в карта `items` носи три или четири букви (`hanzi`,
`pinyin`, `text`) и **може да носи и своя клип** — името му е в
`audio`. Клипът е договор: `pipeline/13_build_reading_audio.py` записва
точно тези имена в `data/audio/`.

- **Дума** (една дума от речника) — не носи име; клипът ѝ идва от
  корпуса.
- **Изречение** — носи име, защото е ръчно написано и не съществува
  никъде другаде.

Бутонът 🔊 се показва **само когато има клип**. Бутон, който не
възпроизвежда нищо, е по-лош от липсващ бутон. Проверката е в
`pipeline/test_curriculum_audio.py`.

## Проверка

```bash
python pipeline/08_build_content_db.py
```

Скриптът спира, ако пътеката е празна или ако някой урок назовава
дума, която речникът няма. Всичко, което е в `curriculum/`, трябва да
е в git — `data/` е gitignored и се презаписва при build.
